# 图片存储优化方案 - 图片分离到单独集合

## 问题背景

当前方案：图片以 base64 直接存入 `dishes` 集合的 `images` 和 `recipeImages` 字段。

**问题：**
- 每个菜品 3 张图 × 100KB = 300KB
- 20 个菜品查询一次 = 6MB，超过微信云数据库**单次查询 1MB 限制**
- 数据库总容量消耗快（免费版 2GB）

## 方案：图片存单独集合

### 核心思路

1. `dishes` 集合只存**文字信息**（名称、分类、描述、菜谱等）
2. 图片存到 `dish_images` 集合，用 `dishId` 关联
3. 查询菜品列表时**只查 dishes**（很小）
4. 点进菜品详情/编辑时**再查图片**

### 数据结构

**dishes 集合（改造后）：**
```json
{
  "_id": "xxx",
  "_openid": "xxx",
  "id": 1234567890,
  "name": "酸辣土豆丝",
  "category": "vegetable",
  "categoryName": "素菜",
  "description": "好吃的土豆丝",
  "recipe": "先切丝再炒...",
  "cookCount": 5,
  "hasImages": true,        // 新增：是否有菜品图
  "hasRecipeImages": true,  // 新增：是否有菜谱图
  "createTime": "2025-01-01T00:00:00.000Z",
  "updateTime": "2025-01-01T00:00:00.000Z"
}
```

**dish_images 集合（新建）：**
```json
{
  "_id": "xxx",
  "_openid": "xxx",
  "dishId": "xxx",          // 关联的菜品ID（dishes._id）
  "type": "dish",           // "dish"=菜品图, "recipe"=菜谱图
  "index": 0,               // 图片顺序（0, 1, 2）
  "base64": "data:image/jpeg;base64,...",  // 图片base64
  "createTime": "2025-01-01T00:00:00.000Z"
}
```

### 需要修改的文件

| 文件 | 修改内容 |
|------|---------|
| `utils/db.js` | 添加图片相关查询/更新方法 |
| `pages/manage/manage.js` | 保存菜品时分开存文字和图片 |

### 实现步骤

#### 1. 云开发控制台操作
- 新建 `dish_images` 集合
- 权限设置为「所有用户可读，仅创建者可写」

#### 2. db.js 添加方法
```javascript
// 保存菜品图片
async saveDishImages(dishId, images, recipeImages) {
  // 先删除该菜品的旧图片
  await this.deleteDishImages(dishId);
  
  // 添加新的菜品图
  for (let i = 0; i < images.length; i++) {
    await this.add('dish_images', {
      dishId, type: 'dish', index: i, base64: images[i]
    });
  }
  
  // 添加新的菜谱图
  for (let i = 0; i < recipeImages.length; i++) {
    await this.add('dish_images', {
      dishId, type: 'recipe', index: i, base64: recipeImages[i]
    });
  }
}

// 查询菜品图片
async getDishImages(dishId, type) {
  const where = { dishId };
  if (type) where.type = type;
  const result = await this.get('dish_images', where, 10);
  return result.data.sort((a, b) => a.index - b.index).map(d => d.base64);
}

// 删除菜品图片
async deleteDishImages(dishId) {
  const result = await this.get('dish_images', { dishId }, 100);
  for (const doc of result.data) {
    await this.remove('dish_images', doc._id);
  }
}
```

#### 3. manage.js 修改 submitDish
```javascript
// 保存菜品（文字和图片分开）
async submitDish() {
  // 1. 处理图片
  let images = [...];  // 压缩后的图片
  let recipeImages = [...];
  
  // 2. 准备菜品数据（不含图片）
  const dishData = {
    name, category, categoryName, description, recipe,
    hasImages: images.length > 0,
    hasRecipeImages: recipeImages.length > 0,
    cookCount: ...
  };
  
  // 3. 保存菜品文字
  if (isEditMode) {
    await db.update('dishes', _id, dishData);
  } else {
    const result = await db.add('dishes', dishData);
    _id = result.data._id;
  }
  
  // 4. 保存图片到单独集合
  await db.saveDishImages(_id, images, recipeImages);
}
```

#### 4. 加载菜品列表时
```javascript
// app.js loadUserData - 只加载文字
const dishesRes = await db.get('dishes');
// dishes 里不包含 base64 图片，所以很小

// 需要显示图片时，按需加载
const images = await db.getDishImages(dishId, 'dish');
```

### 迁移旧数据

需要一个一次性的迁移操作：
1. 遍历 dishes 集合中所有文档
2. 对有 `images` 或 `recipeImages` 字段的菜品，把图片搬到 `dish_images` 集合
3. 删除 dishes 中的 `images` 和 `recipeImages` 字段
4. 添加 `hasImages` 和 `hasRecipeImages` 标记

### 优缺点

**优点：**
- 菜品列表查询不再超 1MB 限制
- 数据库空间消耗大幅降低
- 支持无限多菜品

**缺点：**
- 显示图片需要额外一次查询（稍有延迟）
- 代码改动较大
- 需要手动迁移旧数据
