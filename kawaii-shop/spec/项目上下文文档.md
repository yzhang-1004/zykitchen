## 1. 项目概述

**ZY厨房** 是一款微信小程序，专为情侣/家庭设计的日常点菜工具。用户和女朋友可以共享菜品库、互相点菜、记录烹饪、获得星星奖励。

**核心功能：**
- **点菜页**：浏览菜品、加入购物车、下单到待做清单
- **管理页**：增删改菜品、上传图片、完成待做菜品（得星星）、迁移旧数据
- **我的页**：查看星星数、烹饪记录、头衔系统

**使用场景：** 两个人共享一个菜品库，每天互相点菜，做完菜得星星。

## 4. 数据库结构

所有集合权限统一为：**"所有用户可读，仅创建者可写"**（支持两人互相看到对方数据，但只能修改自己的）。

### 4.1 `dishes` — 菜品（只存文字，不含图片）

```javascript
{
  _id: "xxx",
  _openid: "用户openid",    // 云数据库自动注入
  id: 1234567890,           // 时间戳业务 ID
  name: "酸辣土豆丝",
  category: "vegetable",    // meat | vegetable | noodle
  categoryName: "素菜",
  description: "...",
  recipe: "步骤1\n步骤2",
  ingredients: ["土豆", "青椒", "盐"],  // 食材名称数组（v1.7.0）
  hasImages: true,          // 是否有菜品图（图片在 dish_images 集合）
  hasRecipeImages: false,   // 是否有菜谱图
  cookCount: 5,             // 被做过的次数
  createTime: "2025-...",
  updateTime: "2025-..."
}
```

**重要：** `images` 和 `recipeImages` 字段已清空（旧数据迁移后为空数组 `[]`）。加载时通过 `db.get('dishes', {}, 100, {images: false, recipeImages: false})` 排除这两个字段，避免触发 1MB 查询限制。

### 4.2 `dish_images` — 菜品图片（Base64 存储）

```javascript
{
  _id: "xxx",
  _openid: "当前操作者的openid",
  dishId: "对应 dishes._id",  // 关联字段
  type: "dish" | "recipe",    // dish=菜品图, recipe=菜谱图
  index: 0,                   // 图片顺序
  base64: "data:image/jpeg;base64,...",  // 压缩后的 base64（约 20-40KB）
  createTime: "2025-..."
}
```

**权限说明：** 图片的 `_openid` 是执行操作的人（谁上传/迁移就是谁的）。两人各自操作各自的菜品，图片归属正确。

### 4.3 `cart_items` — 购物车

```javascript
{
  _id: "xxx",
  _openid: "用户openid",
  items: [{ dish: {菜品对象}, quantity: 2 }]
}
```

### 4.4 `todo_orders` — 待做订单

```javascript
{
  _id: "xxx",
  _openid: "用户openid",
  id: 时间戳,
  dishName: "酸辣土豆丝",
  dish: {菜品对象},
  quantity: 1,
  time: "2025/1/1 12:00",
  status: "pending",
  recipeSteps: ["步骤1", "步骤2"]
}
```

### 4.5 `user_stats` — 用户统计

```javascript
{
  _id: "xxx",
  _openid: "用户openid",
  starCount: 15,
  cookHistory: [{ dishName, dishId, time, stars }]
}
```

### 4.6 `temp_openid` — 临时集合（获取 openid 用）

用于在无云函数情况下获取当前用户的 openid：写入一条文档 → 读回获取 `_openid` → 删除临时文档。

## 5. 核心工具类

### 5.1 `utils/db.js` — DB 类（单例导出）

**基础 CRUD：**
- `add(collection, data)` — 自动添加 createTime/updateTime
- `get(collection, where, limit, fields)` — 支持字段过滤（fields 参数）
- `update(collection, id, data)` — 自动更新 updateTime
- `remove(collection, id)`
- `getOpenid()` — 通过 temp_openid 集合获取当前用户 openid

**图片相关：**
- `saveDishImages(dishId, images[], recipeImages[])` — 先删旧图再存新图
- `getDishImages(dishId, type?)` — 查询图片，返回 base64 数组或 {dish:[], recipe:[]}
- `deleteDishImages(dishId)` — 删除菜品所有图片
- `base64ToTempFile(base64)` — base64 写临时文件（**禁止用于跨设备场景**）

**迁移相关：**
- `migrateAllDishes(onProgress, compressFn)` — 逐条迁移旧图片到 dish_images，支持压缩
- `recompressAllDishImages(compressFn, onProgress)` — 重新压缩 dish_images 中的大图片

### 5.2 `utils/upload.js` — 图片处理

**压缩参数（硬性标准）：**
- `maxWidth: 300px`（超过则等比缩放）
- `quality: 25`
- 产出约 **20-40KB** base64

**核心函数：**
- `compressImageToBase64(filePath, quality)` — 本地图片 → 压缩 → base64 data URI
- `compressBase64Image(dataURI)` — 已有 base64 → 写临时文件 → 重新压缩 → 新 base64
- `processImage(filePath)` — 统一入口：
  - `data:` 开头 → 检查大小，超 200KB 重新压缩
  - `cloud://` → 丢弃（返回 null）
  - `http://tmp` / `wxfile://` → 本地临时文件，压缩转 base64
  - 其他 `http` → 网络 URL，保留
  - 其他 → 本地文件，压缩转 base64
- `uploadImages(filePaths, type)` — 批量处理，过滤 null，返回 base64 数组

**路径识别（关键）：**
```
http://tmp/...  → 微信开发者工具本地临时文件 → 需转 base64
wxfile://...    → 真机本地临时文件 → 需转 base64
cloud://...     → 旧云存储路径 → 丢弃
http://其他     → 网络 URL → 保留
data:image/...  → 已有 base64 → 检查大小
```

## 6. 数据流

### 6.1 启动加载

```
app.js onLaunch
  → wx.cloud.init(env: 'cloud1-d8g71kyh480d81f35')
  → loadUserData()
    → db.getOpenid()（通过 temp_openid 集合）
    → Promise.all([
        db.get('dishes', {}, 100, {images:false, recipeImages:false}),  // 排除旧图片字段
        db.get('cart_items', {_openid}),
        db.get('todo_orders', {status:'pending', _openid}),
        db.get('user_stats', {_openid})
      ])
    → 存入 globalData
    → notifyDataLoaded()（触发各页面回调）
```

### 6.2 菜品图片加载（按需）

```
page.loadDishes()
  → 先 setData(allDishes)（无图片，快速显示）
  → 遍历每个菜品，调用 db.getDishImages(dish._id, 'dish')
  → 有图片则更新 allDishes 中对应菜品的 images 字段
  → 重新 setData 刷新 UI
```

### 6.3 新增/编辑菜品

```
manage.submitDish()
  → upload.uploadImages(images) → 压缩转 base64 数组
  → db.update/add('dishes', dishData)  // dishData 不含图片
  → db.saveDishImages(dishId, images, recipeImages)  // 图片存 dish_images
```

### 6.4 数据迁移（管理页按钮触发）

```
manage.migrateData()
  → db.migrateAllDishes(progressCb, upload.compressBase64Image)
    → 逐条读取 dishes（含旧 images 字段）
    → 压缩每张图片（maxWidth 300, quality 25）
    → 存入 dish_images 集合
    → 更新原 dish 文档：hasImages=true, images=[], recipeImages=[]
  → db.recompressAllDishImages(upload.compressBase64Image, progressCb)
    → 逐条读取 dish_images
    → base64 > 50KB 的重新压缩
    → 更新 dish_images 文档
```

## 7. 重要规则与约束

### 7.1 开发规则（必须遵守）

1. **先写方案，经过用户同意才能改代码**（规则 spec.md）
2. **只有用户明确说"提交并推送"才能执行 git 操作**
3. **每次提交推送前必须更新版本号并告知用户**
4. **图片处理禁止使用本地临时文件作为最终存储**（临时文件不能跨设备）
5. **图片压缩参数**：maxWidth 300px，quality 25（硬性标准，不可随意调大）

### 7.2 技术约束

- **云数据库单文档限制**：16MB
- **单次查询结果限制**：1MB（所以 dishes 加载时必须排除 images/recipeImages 字段）
- **微信 `<image>` 组件**：不能渲染过大的 base64 字符串（>100KB 可能不显示）
- **云存储不可用**：免费版有 STORAGE_EXCEED_AUTHORITY 限制，所以图片用 base64 存数据库
- **`_openid` 自动注入**：客户端写入文档时云数据库自动注入，无法手动指定
- **`onLaunch` 不能声明为 async**：否则小程序启动会异常
- **集合名不能以下划线开头**

### 7.3 跨设备访问

- 所有图片必须转为 base64 存入数据库，才能跨设备查看
- `cloud://` 路径因权限问题不可用，必须丢弃
- 本地临时文件路径（`http://tmp/...`、`wxfile://...`）只在当前设备有效，必须转 base64

### 7.4 双人共享权限模型

- 数据库权限"所有用户可读，仅创建者可写"
- 两人可以看到对方创建的菜品和数据
- 只能修改/删除自己创建的内容
- 迁移时：谁执行迁移，图片就归谁（建议各人迁移各人创建的菜品）

## 8. 已知坑与历史问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 查询超 1MB | dishes 含旧 base64 图片 | 排除 images/recipeImages 字段加载 |
| 图片不显示 | base64 太大（>100KB） | 压缩到 maxWidth 300px, quality 25 |
| 上传不转 base64 | `http://tmp` 被当成网络 URL | processImage 单独识别临时文件路径 |
| iOS textarea 内容丢失 | `auto-height` 在 iOS 有 bug | 去掉 auto-height，用固定高度 |
| iOS 编辑弹窗无法滚动 | vh 单位 + 安全区问题 | 改用 % + env(safe-area-inset-bottom) |
| cloud:// 图片 500 错误 | 云存储权限限制 | 丢弃 cloud:// 路径，统一 base64 |
| 删除菜品报集合不存在 | dish_images 集合未创建 | 需手动在控制台创建集合 |
| 迁移后 hasImages 没设置 | update 权限失败 | 各人迁移自己的菜品 |
| `_.remove()` 导致 update 失败 | 操作符兼容问题 | 改用空数组 `[]` 替代 |
